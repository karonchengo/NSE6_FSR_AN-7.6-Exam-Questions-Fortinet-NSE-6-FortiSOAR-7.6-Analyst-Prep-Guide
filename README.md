## What Is the NSE6_FSR_AN-7.6 FortiSOAR Analyst Exam?

## 1. FortiSOAR Architecture and Data Models (20–30%)

This domain evaluates your understanding of FortiSOAR's architecture, deployment models, data structures, access controls, and user interface customization.

Candidates should understand:
- FortiSOAR system architecture and deployment models
- Automation and orchestration concepts
- Navigation and Content Hub functionality
- SOAR and SIEM use cases and differences
- Modules, records, fields, and relationships
- Solution pack content and visual correlation
- Users, roles, teams, and record ownership
- Templates, dashboards, and widgets

A key skill is understanding how FortiSOAR organizes security information and how platform configuration supports operational workflows.

For example, candidates should be able to determine how access controls should be implemented for different teams or how modules and their relationships support incident investigation.

## 2. Playbook Development (25–35%)

Playbook Development is a major exam domain. It focuses on building automation workflows that process security data, apply conditional logic, and execute appropriate actions.

Key topics include:
- Playbook basics, steps, and logic design
- Data ingestion and preprocessing rules
- Conditional logic using if/elif/else statements
- Loops, for-each operations, and loop variables
- Step utility actions and operators
- Jinja filters and expressions
- Dynamic variables, values, and functions
- JSON queries and YAQL statements
- Differences between JSON and YAQL query approaches

Candidates should understand how to construct workflows that make decisions based on input data and perform the required automation actions.

For instance, a playbook might ingest an alert, evaluate its attributes, enrich the associated indicators, and route the incident to the appropriate response workflow. Candidates should know how to configure the logic and data transformations needed to support this process.

## 3. Incident Handling (5–15%)

This domain focuses on using FortiSOAR to coordinate incident response and manage security investigations.

Candidates should understand:
- FortiSOAR incident phases
- Incident-handling workflows
- MITRE ATT&CK Framework integration
- Queue and shift assignment
- War room management
- Correlating records across modules
- Visual correlation and incident phase mapping

The main objective is to understand how FortiSOAR supports structured incident management, task assignment, investigation, and collaboration.

Candidates should also understand how related records and threat information can be connected to give analysts a more complete view of an incident.

## 4. APIs and Connectors (15–25%)

This domain evaluates the ability to integrate FortiSOAR with other security products and external systems.

Important topics include:
- REST API requests and responses
- FortiSOAR API usage
- FortiManager API integration
- Custom connector configuration
- HTTP methods for create, read, update, and delete operations
- REST API triggers
- Differences between REST and JSON-RPC APIs
- Connector creation workflows

API and connector knowledge is essential for automating security operations across multiple tools.

For example, a playbook may need to retrieve information from an external security platform, update an incident record, and initiate a response action. Candidates should understand how APIs, authentication, and connector configuration enable these interactions.

## 5. Troubleshooting (15–25%)

This domain focuses on identifying and resolving problems that affect playbook execution and connector operations.

Candidates should understand:
- Playbook logging levels
- Executed playbook logs
- Step input and output data
- Evaluated arguments
- Troubleshooting Jinja expressions
- Key log files
- Service status checks
- Common playbook and connector issues

A systematic troubleshooting approach is important. Instead of changing multiple configurations without evidence, candidates should inspect logs, validate data transformations, review step inputs and outputs, and identify the point where execution fails.

Understanding Jinja expressions and how data moves between playbook steps is particularly useful when investigating automation failures.
